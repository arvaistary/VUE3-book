# Стиль разработки книги

## Текст

- писать литературным, спокойным русским языком;
- обращаться к читателю на «вы»;
- объяснять риск для пользователя до риска для кода;
- давать русский эквивалент английскому термину при первом употреблении;
- избегать канцелярита, искусственного сленга и повторяющихся вводных фраз.

## Код

- использовать короткие самодостаточные примеры;
- явно показывать контекст, входные данные и ожидаемый результат;
- разделять плохой и хороший пример;
- не включать реальные секреты, доменные значения или внутренние пути;
- подписывать пример версией runtime, только если это нужно для понимания.

## Структура главы

Рекомендуемый порядок: проблема, понятия, плохой пример, разбор ошибки,
хороший пример, ограничения, проверка и упражнение.

## Проверка

Перед переносом в `public/` нужно проверить текст, ссылки, примеры кода и
конфиденциальность. Результаты фиксируются в отчёте work item-а.
