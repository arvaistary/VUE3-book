# Шаблон главы

Скопируйте этот каркас в новый файл главы и замените все пояснения
содержательным текстом. Перед переносом в public/ каркас должен быть
полностью заполнен.

## 1. Учебная цель

Одним предложением опишите, что читатель сможет сделать или объяснить после
главы. Укажите предполагаемый уровень читателя и необходимые предпосылки.

## 2. Ситуация и риск для пользователя

Опишите небольшую нейтральную ситуацию. Начните с того, что почувствует или
потеряет пользователь, если решение устроено плохо.

## 3. Термины

Объясните каждый термин до первого использования в коде. Для англоязычного
термина дайте короткое русское описание и оригинальное написание в скобках.

## 4. Минимальная задача

Сформулируйте одну задачу, которую решают оба варианта. Перечислите вход,
ожидаемый результат и способ локальной проверки.

## 5. Плохой пример

~~~js
// Небольшой синтетический пример с одной намеренной проблемой.
function badExample(input) {
  return input;
}
~~~

После кода объясните, почему вариант выглядит правдоподобно, где возникает
риск и как этот риск проявится для пользователя или команды.

## 6. Хороший пример

~~~js
// Улучшенный пример той же задачи и того же контекста.
function goodExample(input) {
  return input;
}
~~~

Объясните, какая ответственность стала яснее, какое поведение теперь можно
проверить и какую цену имеет улучшение.

## 7. Сравнение и ограничения

Сопоставьте варианты по поведению, читаемости, тестируемости и сопровождению.
Укажите случаи, в которых хороший вариант не является лучшим выбором.

## 8. Упражнение

Дайте маленькое задание, которое можно выполнить без доступа к исходному
проекту. Приведите критерии самопроверки, но не подменяйте ими решение.

## Критерии готовности главы

- цель и предпосылки понятны без соседней главы;
- термины объяснены до примеров;
- плохой и хороший варианты решают одну задачу;
- последствия и компромиссы названы явно;
- пример проверяется локально;
- в тексте нет внутренних деталей и незаполненных пояснений.
