# Brief части 6. Качество изменений

## Учебная цель

После части читатель сможет сделать контракт данных явным, выбрать небольшой
тест для чистой функции и провести code review по наблюдаемому риску, а не по
личному вкусу. Уровень — начинающий разработчик, осваивающий TypeScript и
автоматические проверки.

## Аудитория и предпосылки

Нужны базовые JavaScript и понимание функций. TypeScript, типы результата и
утверждения в тестах будут введены до примера.

## Термины

Статическая типизация, контракт, чистая функция, unit-тест (модульная
проверка), assertion (утверждение), code review, регрессия.

## Минимальная задача и пара примеров

Одна задача для обоих вариантов: безопасно сформировать подпись карточки
товара по входному объекту и проверить граничный случай. Плохой вариант
принимает `any` и проверяет только удачный случай; хороший описывает контракт,
выделяет чистую функцию и проверяет пустое значение.

## Ограничения

Типы не заменяют проверку данных, пришедших из сети. Unit-тест не доказывает,
что компонент правильно смонтирован, а длинный список слабых тестов может
создать ложную уверенность.

## Критерии готовности

- контракт объяснён до TypeScript-кода;
- два варианта делают одну операцию;
- тест проверяет результат и границу;
- review-вопросы отделяют факт от предположения.

## Источники и проверка

Проверка терминов: [TypeScript — The Basics](https://www.typescriptlang.org/docs/handbook/2/basic-types.html)
и [Vitest — Getting Started](https://vitest.dev/guide/). TypeScript-фрагмент
проверяется компилятором проекта или чтением типов, а тест — выполнением
описанного assertion.
