# Data Model: Читательский аудит

Работа не использует базу данных. Модель описывает записи в Markdown-отчёте и
нужна для единообразной фиксации результата.

## ReaderProfile

Описывает точку зрения прохода.

| Поле | Значение |
|---|---|
| `id` | `beginner` или `middle` |
| `knowledge` | допустимые предпосылки чтения |
| `questions` | вопросы, на которые должен ответить проход |
| `result` | ожидаемое понимание после прохода |

Обязательные профили: начинающий и middle-разработчик. Проходы выполняются в
этом порядке.

## AuditTarget

Публичный материал, который нужно проверить.

| Поле | Значение |
|---|---|
| `path` | путь внутри публичного маршрута чтения |
| `kind` | README, contents, introduction или chapter |
| `position` | раздел, заголовок или диапазон строк для отчёта |
| `profiles` | один или оба reader-профиля |
| `status` | `planned`, `reviewed`, `needs-fix` или `blocked` |

Набор targets включает `public/README.md`, `public/contents.md`, введение и
восемь частей.

## Finding

Одно наблюдаемое читательское замечание.

| Поле | Значение |
|---|---|
| `id` | стабильный идентификатор, например `RA-001` |
| `profile` | `beginner`, `middle` или `both` |
| `category` | маршрут, доступность, терминология, пример, техника, privacy или стиль |
| `target` | ссылка на `AuditTarget` и точное место |
| `observation` | что читатель видит или не может сделать |
| `impact` | влияние на понимание, проверку или безопасность |
| `recommendation` | предлагаемое исправление |
| `resolution` | фактическое изменение или причина блокировки |
| `status` | `open`, `fixed`, `deferred` или `blocked` |
| `evidence` | команда, ручной сценарий или ограничение проверки |

`deferred` допустим только для неблокирующего улучшения, которое не снижает
понятность, автономность, базовую техническую корректность или публичную
безопасность; для него нужны причина, безопасная альтернатива и следующее
действие. `blocked` означает, что материал нельзя считать публикационно
готовым, поэтому такой статус запрещает завершение work item-а.

## ChapterVerdict

Итог по одной главе и reader-профилю.

| Поле | Значение |
|---|---|
| `chapter` | имя публичной главы |
| `profile` | `beginner` или `middle` |
| `checklist` | результат проверки обязательных элементов |
| `findings` | список связанных `Finding.id` |
| `verdict` | `pass`, `needs-fix` или `blocked` |

Глава получает `pass` только после закрытия связанных замечаний и повторного
прохода.

## EvidenceRecord

Подтверждение результата.

| Поле | Значение |
|---|---|
| `kind` | команда, локальный запуск, ручной walkthrough или privacy review |
| `command_or_method` | точная команда или описание метода |
| `result` | наблюдаемый результат |
| `related` | `Finding.id`, `AuditTarget.path` или критерий спецификации |
| `date` | дата проверки |

Evidence не заменяет исправление: оно только подтверждает, что заявленный
результат действительно проверен.

## Relationships and lifecycle

```text
ReaderProfile -> ChapterVerdict -> AuditTarget -> Finding -> EvidenceRecord
```

Жизненный цикл замечания:

```text
open -> fixed -> rechecked
  \-> deferred (reason + next action)
  \-> blocked (safe alternative + no public transfer)
```
