# Research: Технический аудит Nuxt 3 и Nuxt 4

## Контекст

Публичная книга уже использует Nuxt как технологический контекст, но её
публичная ценность зависит от точности именно тех мест, где меняются версия,
структура каталогов, SSR-загрузка данных и окружение. Исходный курс не является
публикуемым техническим источником: он помогает определить темы, а проверяемые
факты берутся из официальной документации и синтетических примеров.

## Решения

### 1. Официальная документация — источник версионных фактов

Для Nuxt 3 и Nuxt 4 используются официальные страницы `nuxt.com/docs`. На дату
аудита проверяются:

- [Nuxt 4 Upgrade Guide](https://nuxt.com/docs/4.x/getting-started/upgrade);
- [Nuxt 4 Directory Structure](https://nuxt.com/docs/4.x/directory-structure);
- [Nuxt 4 Data Fetching](https://nuxt.com/docs/4.x/getting-started/data-fetching);
- [Nuxt 4 Runtime Config](https://nuxt.com/docs/4.x/guide/going-further/runtime-config);
- [Nuxt 4 App Plugins](https://nuxt.com/docs/4.x/directory-structure/app/plugins);
- [Nuxt 4 App Middleware](https://nuxt.com/docs/4.x/directory-structure/app/middleware);
- [Nuxt 4 Server Directory](https://nuxt.com/docs/4.x/directory-structure/server);
- [Nuxt 3 Directory Structure](https://nuxt.com/docs/3.x/directory-structure);
- [Nuxt 3 Data Fetching](https://nuxt.com/docs/3.x/getting-started/data-fetching);
- [Nuxt 3 Runtime Config](https://nuxt.com/docs/3.x/guide/going-further/runtime-config).

Дата проверки фиксируется в audit report. Быстро меняющиеся сведения о
поддержке и конкретных версиях не переносятся без подтверждения на странице.

### 2. Миграция описывается как проверяемая последовательность

Nuxt 4 вводит новую структуру с `app/` как каталогом приложения, тогда как
`server/`, `public/` и `shared/` относятся к корню проекта. При этом старая
структура может быть автоматически распознана, а явный пользовательский
`srcDir` требует отдельной проверки. Поэтому книга должна показывать
инвентаризацию, автоматизацию механической перестановки и проверку результата,
а не универсальную команду «переместить всё».

### 3. SSR-загрузка данных проверяется по назначению API

`$fetch` подходит для событийных клиентских действий и простого запроса, но
вызов в setup-коде при универсальном рендеринге может привести к повторной
загрузке во время hydration. `useFetch` и `useAsyncData` связывают результат с
payload Nuxt. В тексте нужно объяснить не только названия функций, но и
условие, при котором каждая из них уместна.

### 4. Общий код ограничен двумя средами

`shared/` предназначен для кода, который используется приложением Vue и
сервером Nitro. Он не должен импортировать Vue, Nitro, браузерные API или
серверные модули. В книге остаётся короткая чистая функция, а composable и
server-only операции показываются в своих средах.

### 5. Runtime-конфигурация разделяет публичное и серверное

Ключи внутри `runtimeConfig.public` доступны браузеру и попадают в публичный
контекст. Приватные ключи предназначены для серверной среды. Имена переменных
окружения должны соответствовать структуре конфигурации и начинаться с
`NUXT_`; реальные значения и секреты в книге не используются.

### 6. Полный runtime Nuxt в книге не является обязательным тестом

В репозитории книги нет Nuxt-приложения и зависимости, а добавление такой
зависимости расширило бы scope. Поэтому Nuxt-фрагменты проверяются статически и
по официальным примерам, автономные JS/TS-функции — локально через Node.js.
Отсутствие запуска Nuxt фиксируется явно и не превращается в ложное
утверждение о runtime-прохождении.

## Отклонённые альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| Сверять текст только с исходным курсом | Курс не является безопасным публичным источником и не заменяет актуальную документацию API |
| Установить Nuxt в корень книги | Это добавляет зависимость и приложение, не нужные для Markdown-аудита, и смешивает учебную фикстуру с рукописью |
| Описать только новую структуру Nuxt 4 | Читателю нужен переход от исходной точки Nuxt 3 и ограничения совместимости |
| Сохранить тезис о сроке поддержки без первичного источника | Версионный статус быстро меняется; неподтверждаемое утверждение снижает точность книги |
| Перенести реальные примеры курса | Это нарушает privacy-границу и делает книгу зависимой от закрытого контекста |

## Неизвестные, не блокирующие план

Будущие версии Nuxt, конкретные версии модулей, издательский формат и
внутренняя структура исходного приложения не входят в этот work item. Книга
будет описывать проверяемые концепции и указывать дату сверки ссылок.
