# Дополнительные gates книги

## Public boundary

В `public/` не допускаются реальные имена исходного проекта, внутренние пути,
ветки, API-адреса, конфигурационные значения, секреты, персональные данные и
ссылки на закрытые системы.

## Editorial quality

Каждая глава должна содержать цель, объяснение терминов, плохой и хороший
пример, разбор компромиссов и самостоятельное упражнение либо проверочный
вопрос.

## Code examples

Пример должен быть синтетическим, минимальным, понятным без внутреннего
репозитория и согласованным с заявленным runtime. Плохой пример нельзя
оставлять без пояснения, почему он опасен.

## Reproducibility

Проверки должны запускаться из корня книги. Если пример требует внешнего
сервиса, в тексте нужен локальный заменитель или честно описанное ограничение;
недоступную проверку нельзя объявлять пройденной.
