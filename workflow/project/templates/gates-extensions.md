# Расширения gates — <название проекта>

Этот документ содержит только проверки, специфичные для стека или домена.
Универсальные gates, workflow contract, scope, provenance и Evidence Index
остаются в [`workflow/core/`](../../core/README.md).

Для каждого gate укажите: когда он нужен, что именно проверяет, какую ошибку
блокирует, какой конкретный тест или запуск команды это подтверждает и какой
маркер записывается в DoD report. Описание должно позволять повторить
проверку по шагам.

## Gate C — Авторизация и capability security

**Применяется при:** `<новые endpoints, роли, capability или public access>`.

Опишите матрицу прав: кто вызывает операцию и какой результат должен получить.
Зафиксируйте порядок проверки прав и входных данных, ожидаемые `403`/`404`/
доменные `422`, отсутствие возможности угадывать чужие идентификаторы,
разрешённый список публичных полей, отзыв capability и запрет обхода
авторизованной мутации.

## Gate D — Состояния и mutation inventory

**Применяется при:** `<состояния, freeze, pending, soft delete или изменение данных>`.

Для каждой операции укажите, что происходит в замороженном состоянии, при
открытом pending-процессе и после soft delete родителя. Результат должен быть
конкретным: код ошибки, `404`, разрешённое чтение или обоснованный `N/A`.
Рядом укажите тест, который это подтверждает.

## Gate E — Side effects

**Применяется при:** `<event/listener/job/webhook/notification/audit>`.

Опишите границу транзакции, поведение после commit, duplicate/rollback,
проверку реальной связки producer → handler → queue и правила для stub.
Укажите конкретный тест и маркер, который закрывает gate.

## Gate F — Batch и concurrency

**Применяется при:** `<batch mutation или race-sensitive operation>`.

Опишите порядок блокировок, атомарность, результат конфликта,
production-like окружение, число повторённых запусков и почему local-only или
skipped-проверка не считается достаточной.

## Gate H — E2E и ручной сценарий

**Применяется при:** `<обязательный browser/API E2E или collection>`.

Укажите каталог сценариев, каталог fixtures, токены/переменные, пошаговый
runbook, ограничения маршрутов и команду, которую повторно запускает adapter.

## Gate I — Adversarial input / parser

**Применяется при:** `<upload/parser/import/templating/untrusted input>`.

Перечислите повреждённые данные, границы размера, альтернативные кодировки,
подменённый тип, переполнение ресурсов и другие небезопасные входы. Тест должен
проверять заявленный контракт, а не только отсутствие очевидного сбоя в happy
path.
