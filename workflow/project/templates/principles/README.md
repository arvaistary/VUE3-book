# Принципы проекта — <название проекта>

Индекс долгоживущих правил project adapter-а. Эти документы читаются перед
реализации нетривиальной задачи и меняются редко; конкретная задача хранит
свой contract (контракт) в `spec.md`, а не в principles.

## Рекомендуемый состав

| Документ | Для кого | Когда обязателен |
|----------|----------|------------------|
| `best-practices.md` | агент и человек | всегда |
| `anti-patterns.md` | агент и человек | всегда |
| `workflow-patterns.md` | агент | состояния, согласие, workflow, побочные эффекты |
| `code-review-mistakes.md` | агент и reviewer | перед сдачей нетривиальной задачи |

## Правила содержания

Каждый принцип должен содержать короткое правило, объяснение, минимальный
пример, запрещённый вариант и способ проверить соблюдение. Ссылки на команды,
пути и runtime должны согласовываться с `stack.md` и профилем.

Не переносите в principles одноразовые решения конкретной задачи. Не ослабляйте
`workflow/core/` и не объявляйте обязательный маркер доказательства выполненным
без актуального теста, команды или runtime-вывода.
