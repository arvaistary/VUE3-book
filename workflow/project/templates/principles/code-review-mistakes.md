# Типичные ошибки код-ревью — <название проекта>

Перед финализацией reviewer проверяет не только успешный сценарий (happy path),
но и типовые провалы:

| Область | Вопрос ревью |
|---------|--------------|
| Состав изменений | `<нет ли файлов вне allowlist и служебных следов?>` |
| Права | `<проверены ли все варианты actor/result и ошибочный ввод?>` |
| Состояния | `<каждая операция учтена для freeze/pending/delete?>` |
| Контракт | `<spec, код, API/docs и tests согласованы?>` |
| Побочные эффекты | `<есть ли реальная связка и проверка после commit?>` |
| Доказательства | `<каждый PASS указывает на текущую команду/test/runtime?>` |
| Безопасность | `<нет ли утечки PII, capability или обхода мутации?>` |

Добавляйте в таблицу новые повторяющиеся ошибки только вместе с конкретным
способом их обнаружения.
