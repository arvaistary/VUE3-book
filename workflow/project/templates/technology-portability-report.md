# Отчёт о переносимости технологий — <название проекта>

## Вывод

Опишите, какие обязанности остаются универсальными в `workflow/core/`, а какие
реализованы в project adapter-е. Укажите, на каком стеке, в каком окружении и
какими командами проводилась проверка.

| Слой | Ответственность |
|------|-----------------|
| `workflow/core/` | жизненный цикл, общий contract, scope, provenance и evidence |
| `workflow/project/` | адаптер runtime, структурные/смысловые проверки, principles |
| `technology-profile.env` | команды, названия окружений и роли артефактов |
| канонический `spec.md` | домен, состояния, права, privacy и обязательные доказательства |

## Модель переноса

Опишите по шагам:

1. что копируется из `workflow/core/` без технологических деталей;
2. какие файлы создаются из `workflow/project/templates/`;
3. как проверяется profile и запускается smoke work-item;
4. как подтверждаются обязательные runtime, E2E и concurrency-проверки;
5. какие старые briefs требуют перехода на `artifact:<role>`.

## Известные ограничения

Зафиксируйте непроверенные режимы, ограничения runtime, отсутствующие
смысловые проверки и условия, при которых `READY` нельзя считать готовностью
продуктового изменения.

## Доказательство переноса

Укажите commit/base_ref smoke work-item, команды verify/lint/finalize, runtime,
результат Evidence Index и дату проверки. Не заменяйте фактический вывод
общей фразой «проверено».
